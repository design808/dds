# DDS 화면 설계

DDS가 연결된 프로젝트에서 실제 사용자 작업에 맞는 화면을 설계하고 구현한다. 컴포넌트 견본의 배치와 문구를 페이지 구성으로 복사하지 않는다. 이 skill은 색상·서체·토큰·컴포넌트를 생성하지 않는다.

## 먼저 확인할 기준

- 프로젝트의 DDS 적용 기록에서 설치 위치와 버전을 찾는다. 설치한 `ui/README.md`, `ui/registry.json`, `ui/composition.md`, 필요한 컴포넌트 원본을 읽는다. 웹 문서가 더 최신이어도 설치 버전을 임의 변경하지 않는다.
- 프로젝트의 저장 프로필과 연결 CSS가 있으면 그대로 사용한다. 저장한 브랜드색·제목/본문 서체·기능 색상은 기본 DDS 값보다 우선한다. 브라우저의 미저장 미리보기를 프로젝트 설정으로 취급하지 않는다.
- 현재 프레임워크·의존성·실제 콘텐츠·제출값·권한·서비스 이벤트를 확인한다. 기존 서비스 개선에서는 원래 기능과 사용자 수정을 보존한다.
- 새 서비스는 이번 요구와 프로젝트에 제공된 DDS 자료에서 출발한다. 다른 프로젝트의 브랜드·화면·과거 대화별 취향을 자동으로 끌어오지 않는다.

## 설계와 구현

아래 판단을 실제 작업에 반영한다. 단순 수정은 필요한 부분만 적용하고, 문서 작성 자체를 목표로 삼지 않는다. 상세 기준은 [화면 설계와 검토](references/page-design.md)를 읽는다.

1. **목적과 콘텐츠를 정한다.** 누가 어떤 일을 완료해야 하는지, 첫 화면에서 필요한 정보와 뒤로 미룰 정보를 구분한다. 서비스 소개·탐색·작성·진행·결과 화면을 같은 틀로 다루지 않는다. 요구가 짧으면 합리적인 범위를 정해 진행하고 결과에 주요 가정을 알린다. 핵심 기능·대상·콘텐츠를 결정할 수 없을 때만 질문한다.
2. **배치 근거를 찾는다.** 적합한 실제 화면이나 제공된 참고 자료에서 탐색·본문·주요 행동의 관계, 정보 밀도와 모바일 전환을 살펴본다. 관찰한 구조와 현재 작업에 맞는 이유를 기록한다. 참고 화면의 코드·스타일·브랜드를 가져오지 않는다. 자료를 볼 수 없으면 본 것처럼 말하지 않고 요구사항에서 설계한다.
3. **핵심 화면의 구조를 비교한다.** 구조 선택이 중요한 경우 동일한 실제 콘텐츠로 서로 다른 배치를 짧게 비교한다. 색상·서체만 바꾼 안을 레이아웃 대안으로 취급하지 않는다. 사용자의 작업·정보 우선순위·좁은 화면에서의 흐름으로 선택한다. 모든 페이지에 여러 안을 만들거나 매번 승인 대기를 추가하지 않는다.
4. **DDS 원본으로 구현한다.** 컨트롤 높이·글자·내부 패딩·색·경계·모서리·상태는 공식 규격을 유지한다. 가용 폭·페이지 그리드·외부 여백·필요한 영역 높이는 서비스에서 설계한다. 입력·목록·탭 본문은 부모 폭을 사용하고 버튼·아이콘·달력·팝업은 공식 고유 크기를 따른다. 문서의 440px 제한·가운데 정렬·축소·견본 미디어 프레임을 복사하지 않는다. 공통 배치 정책은 `ui/dds.css`에 포함되어 있으므로 `component-layout.css`를 중복 로드하지 않는다. 문서 전용 `component-specimens.css`는 서비스에 연결하지 않는다. 설명·상태·날짜·배지·보조 행동은 필요한 경우에만 제공한다. 필요한 구조가 없으면 기존 원본의 적합한 변형·슬롯·어댑터를 먼저 확인한다.
5. **실제 렌더링을 검토한다.** PC와 모바일 화면을 보고 첫 시선, 정보 위계, 밀도, 빈 공간, 긴 콘텐츠와 상태 변화를 판단한다. 부모 폭 240·320·510·800px와 Grid/Flex에서 폭 적응을 확인한다. 모달의 전체 폭 필드·2열의 각 필드·실제 미디어 슬롯에 견본 크기나 프레임이 남지 않는지 본다. 기능 검사가 통과해도 시각 검토가 끝난 것은 아니다. 관찰한 문제를 수정하고 변경한 부분을 다시 확인한다. 가능하면 구현 맥락을 모르는 별도 검토자가 화면을 보게 한다. 실제 브라우저를 확인하지 못한 경우에는 확인 범위를 명시한다.

서비스 헤더는 전체 헤더 폭에 연결하고 내용만 `--dds-topnav-content-width`(좌우 여백 포함)·`--dds-topnav-gutter`로 제한한다. 하단 경계는 바깥 헤더에 유지한다. 테마 전환은 푸터에 아이콘 버튼 하나로 제공하며 기존 provider·저장 키를 재사용한다. 열린 모달의 기본 그룹 간격은 원본을 따르고 문서 견본의 상하 margin은 복사하지 않는다.

## 선택적 참고 검색

막연한 스타일 키워드 대신 한 가지 설계 문제를 검색한다. 이 skill 폴더의 절대 경로로 실행하며 Node.js 18 이상만 필요하다.

```text
node <skill-directory>/scripts/search.mjs "search directory" --domain layout --json
node <skill-directory>/scripts/search.mjs "form validation" --domain ux --json
```

- `layout` 결과는 주로 소개·랜딩 페이지의 섹션 구성 참고다. 목록·편집기·진행 화면에 히어로·후기·가격표를 강제로 추가하지 않는다.
- 결과는 검토할 후보이며 품질 점수나 완성된 화면이 아니다. 사용자 목적과 맞지 않으면 버린다. 결과가 없으면 이를 구분하고 일반 설계 판단으로 진행한다.
- 참고 자료의 수치·규칙이 설치한 DDS와 다르면 DDS와 저장 프로필을 유지한다. 접근성 문제를 발견하면 사실과 적용 범위를 알리고, 기존 예외를 충족했다고 보고하지 않는다.
- 새 디자인 시스템, 팔레트, 폰트 조합, 간격 스케일, 스타일 프리셋을 생성하거나 별도 UI·애니메이션 라이브러리를 설치하지 않는다.

## 결과 전달

작동하는 화면과 간단한 설계 근거, 실제 확인한 조건과 남은 기능 범위를 전달한다. 디자인 시스템 설명·설계 메모·검토용 문구를 제품 화면에 넣지 않는다. 확인되지 않은 통계·후기·저장 완료·통화 연결 같은 상태를 실제 결과처럼 표시하지 않는다. 설치나 코드 준비만으로 운영 기능이 연결됐다고 보고하지 않는다.
