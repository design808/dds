# DDS 페이지 구성 기준

DDS는 버튼·입력·상태 표현과 조작 방식을 맞춘다. 화면의 목적, 정보 순서와 서비스 문구는 해당 서비스에서 결정한다. 컴포넌트 원본을 사용했다는 사실만으로 사용하기 좋은 화면이 완성되지는 않는다.

## 원본에서 유지할 것과 선택할 것

| 구분 | 적용 방법 |
| --- | --- |
| 디자인 규격 | 컨트롤 높이, 글자 역할, 내부 패딩, 색, 경계, 모서리, 포커스, 아이콘과 상태 표현은 원본·공식 variants를 사용한다. |
| 필수 구조 | 라벨과 입력의 연결, 탭과 패널, 메뉴 트리거와 패널, 폼과 제출 버튼의 관계를 유지한다. |
| 선택 콘텐츠 | 설명, 글자 수, 상태, 날짜, 배지, 보조 행동은 필요한 항목만 넣는다. `optional`과 실제 콘텐츠를 사용한다. |
| 견본 콘텐츠·배치 | 예제 제목·안내 문구·개수·날짜와 문서의 440px 폭 제한·가운데 정렬·축소·미디어 프레임은 서비스 배치로 복사하지 않는다. |
| 페이지 구성 | 가용 폭, 그리드, 섹션 순서, 외부 여백과 필요한 영역 높이는 실제 작업과 콘텐츠에 맞춘다. |

검색창 아래 설명은 모든 검색에 필요한 요소가 아니다. 라벨과 placeholder만으로 충분하면 생략한다. 정해진 입력 형식이나 검색 범위를 추가로 알려야 할 때만 도움말을 넣는다. 결과 개수는 결과 제목 옆 한 곳에서 표시하고 검색창 아래에서 반복하지 않는다.

선택 콘텐츠를 생략하면 그 콘텐츠에 딸린 여백과 빈 래퍼도 남기지 않는다. Alert는 제목과 설명이 모두 있을 때만 사이 간격을 두며, 제목·설명은 선택한 상태의 글자색을 함께 사용한다. 서비스에서 제목이나 설명을 제거하려고 페이지 CSS로 컴포넌트 내부 여백을 다시 정의하지 않는다.

입력·목록·탭 본문은 부모 폭에 맞추고, 버튼·아이콘·달력·팝업의 실제 고유 크기와 공식 변형은 유지한다. 공통 배치 정책인 `component-layout.css`는 `ui/dds.css`에 포함된다. 문서 전용 `component-specimens.css`는 서비스에 연결하지 않는다. 스크롤 영역의 높이는 필요할 때 부모의 `--dds-scroll-height`·`--dds-scroll-max-height`로 정한다. 기본값은 `auto`·`none`이다.

탭 목록은 항목이 가용 폭을 넘을 때만 가로로 스크롤한다. 일반 항목에서 생기는 스크롤이나 탭의 세로 스크롤은 정상 상태가 아니다. 밑줄·초점 표시가 영역 밖으로 나가 스크롤을 만들지 않는지, 실제 페이지의 좁은 열과 긴 항목에서도 확인한다. 페이지나 컴포넌트에 `overflow:hidden`을 덧대어 잘림을 숨기지 않는다.

Top navigation은 전체 헤더 폭의 부모에 연결하고, 내부 콘텐츠 폭과 좌우 여백은 부모의 `--dds-topnav-content-width`·`--dds-topnav-gutter`로 정한다. 콘텐츠 최대 폭에는 좌우 여백이 포함된다. 하단 경계는 바깥 헤더에 유지하며 `100vw`나 음수 여백으로 부모를 벗어나게 하지 않는다. 테마 전환은 헤더 대신 푸터에 아이콘 버튼 하나로 두고 현재 기능 이름과 hover·키보드 탐색 툴팁을 제공한다. 기존 테마 provider와 저장 키를 재사용한다.

## 대시보드 현황

현황 카드는 Card와 Icon을 조합한다. `ui/index.js`의 `metricContent(options, icon)`은 라벨·항목 아이콘·현재 값·증감 표시를 같은 원본으로 만든다. `.dds-ui` 안에서 호스트에 `.dds-content-card.dds-metric`을 적용한다. 섹션 제목의 장식 아이콘과 달리 항목 아이콘은 방문자·가입·전환 등 지표를 식별하는 용도로 쓴다.

```js
import {metricContent, icon} from './ui/index.js';

const card = document.createElement('article');
card.className = 'dds-content-card dds-metric';
card.innerHTML = metricContent({
  label: '이탈률', icon: 'LogOut',
  value: 40.8, previous: 42.8, digits: 1, unit: '%',
  mode: 'points', better: 'lower', comparison: '이전 30일 대비'
}, icon);
document.querySelector('.dds-ui').append(card);
```

- 항목 아이콘은 의미에 맞는 Lucide를 사용하고, 증감은 방향 아이콘과 증가·감소·변화 없음 문구를 함께 표시한다.
- `better:'higher'`는 증가가 긍정, `'lower'`는 감소가 긍정이다. 판단하지 않은 지표는 기본값 `'neutral'`을 사용한다. 긍정은 `--success`, 부정은 `--destructive`, 중립은 `--text-secondary`다. 수치의 방향과 평가 색상을 혼동하지 않는다.
- `mode:'relative'`는 이전 값 대비 증감률(%), `'points'`는 비율 간 차이(%p), `'absolute'`는 실제 값의 차이다. 같은 기간·정의·단위의 실제 값을 전달하고 `comparison`에 비교 기준을 명시한다. 문서 블록의 합성 수치를 서비스 데이터로 복사하지 않는다.
- `previous`를 생략하면 증감 영역도 생략한다. `null`은 비교 데이터 없음, 이전 값이 0 이하인 상대 증감률은 계산 불가로 표시한다. 0에서 0으로 유지되면 변화 없음이다. 색이나 화살표로 없는 변화를 만들지 않는다.
- `digits`는 현재 값, `changeDigits`는 증감의 표시 정밀도다. 금액 등 별도 표시 형식은 `valueText`로 전달하되, 비교 계산에는 숫자 `value`와 `previous`를 사용한다. 라벨·표시 문구는 이스케이프한다.
- 읽기 전용 현황은 정적 요소로 표시한다. 실제로 상세 이동이나 그래프 선택을 수행할 때만 링크 또는 버튼을 사용한다. 버튼으로 지표를 선택하면 `aria-pressed`를 갱신하고 실제 그래프도 함께 바꾼다. 선택 경계는 지표의 긍정·부정 색상과 분리한다.

## 목록·탐색 화면

- 검색·분류·필터·정렬·결과가 서로 가까운 하나의 흐름이 되도록 배치한다. 각각을 큰 섹션으로 벌리지 않는다.
- 입력 즉시 결과를 바꾸는 방식과 버튼으로 검색을 실행하는 방식 중 하나를 선택한다. 두 동작을 별개로 제공하면 각각의 목적을 구분한다.
- 카드에서는 제목과 선택에 필요한 조건을 먼저 보여준다. 채용공고라면 기업·직무·지역/경력·마감일을 우선하고 산업·등록일·부가 태그는 필요에 따라 생략한다.
- 개수는 실제 결과에서 계산한다. 선택한 필터, 결과 없음, 초기화와 새로 불러오는 상태를 함께 설계한다.
- 반복 목록의 열 수와 정보량은 실제 긴 제목과 마지막 행으로 확인한다. 좁은 화면은 내용의 우선순위를 유지하며 한 열로 바꾼다.

### 구분선형 목록

각 항목을 별도 카드로 감쌀 필요가 없으면 Item의 `appearance: 'divided'`를 사용한다. 외곽 테두리·모서리·배경 없이 행 사이 구분선으로 나눈다. 제목·조건은 본문, 마감일처럼 짧은 값은 후행 정보, 북마크·메뉴는 별도 행동 영역에 둔다. 상세로 이동하는 링크와 별도 버튼을 중첩하지 않는다.

목록의 폭과 바깥 여백은 페이지에서 정한다. 긴 제목과 조건은 줄바꿈하고 후행 정보·버튼의 자리를 확보한다. 목록 컨테이너 480px 이하에서는 후행 정보가 다음 줄로 내려가며 별도 행동은 오른쪽에 유지된다. 카드 자체가 독립된 정보 단위일 때는 Card나 List card를 선택한다.

## 블록을 참고하는 방법

새 페이지나 큰 레이아웃 변경에서는 작업에 맞는 블록을 찾아 정보 순서·컴포넌트 조합·모바일 전환을 참고한다. 블록 전체를 페이지에 넣거나 같은 배치를 강제하지 않는다.

| 만들 화면 | 참고 블록 | 확인할 구성 |
| --- | --- | --- |
| 공고·문서 탐색 목록 | [채용 공고 목록](https://design808.github.io/dds/#/blocks?block=job-list) | 구분선형 Item, 제목·조건·후행 정보, 독립 행동 |
| 여러 열을 비교하는 관리 목록 | [블록의 기본 표](https://design808.github.io/dds/#/blocks) | Table, 검색·필터·행동, 좁은 화면의 내부 스크롤 |
| 로그인·가입 | [블록의 로그인·회원가입](https://design808.github.io/dds/#/blocks) | Field, 오류 안내, 제출 행동의 순서 |
| 업무 진행 현황 | [블록의 칸반](https://design808.github.io/dds/#/blocks) | 열 구분, Card·Badge·Avatar 조합 |
| 서비스 공통 영역 | [블록의 헤더·푸터](https://design808.github.io/dds/#/blocks) | Top navigation, 푸터 링크와 테마 전환 |

블록의 CSS·스크립트는 DDS 웹 문서용이다. 서비스에는 설치한 `ui/registry.json`의 컴포넌트와 `ui/dds.css`를 사용하고 실제 데이터·이벤트를 연결한다. 미리보기의 고정 폭·축소·여백과 예제 문구는 복사하지 않는다. 채용 공고 목록 블록의 기업·공고는 가상 데이터이며 서비스 기본 데이터로 사용하지 않는다. 웹 블록이 설치 버전보다 최신이면 지원하는 구조만 참고한다. 웹에 접근할 수 없어도 위 구성 기준과 설치 원본으로 진행하며, 보지 않은 블록을 확인했다고 보고하지 않는다.

## 작성·편집 화면

- 같은 목적의 필드를 한 묶음으로 두고 라벨·도움말·오류를 해당 필드에 붙인다. 필드 사이 구분선을 모든 곳에 넣지 않는다.
- 필수 표시, 입력 제한과 글자 수는 실제 제출 규칙과 연결한다. 견본의 `maxlength`, 날짜, 체크 상태를 서비스 기본값으로 사용하지 않는다.
- 작성 후 실행할 행동은 작성 흐름 마지막에 둔다. 길어서 고정 행동이 필요하면 본문을 가리지 않도록 공간을 확보한다.
- 오류는 문제가 있는 필드와 복구 방법을 안내한다. 모든 저장·검증에 상단 Alert나 모달을 반복하지 않는다.
- 모달 본문에는 폼·목록·설명 중 필요한 내용을 넣는다. 예제의 문서 미리보기 상자까지 감싸지 않는다.
- 열린 모달의 기본 그룹 간격은 원본이 제공한다. 예제 문서의 상하 margin을 복사하지 않으며 슬롯 안의 필드·문단 간격만 서비스에서 정한다.
- 모달의 필드는 본문 폭을, 2열 폼의 필드는 각 셀의 폭을 채운다. 필드 내부에 문서 견본의 폭 제한을 남기지 않는다.

## 상세·결과 화면

- 주 제목, 핵심 상태, 본문, 다음 행동의 순서를 먼저 정한다. 모든 텍스트를 같은 크기·굵기로 표시하지 않는다.
- 긴 본문과 결정에 필요한 요약 정보는 구분한다. 보조 열이 필요 없는 화면에 빈 사이드바를 만들지 않는다.
- 차트는 사용자가 비교할 값과 단위를 먼저 정하고 형태를 고른다. 장식용 수치·비율·완료 상태를 넣지 않는다.
- 카드 경계는 반복 항목이나 독립된 정보 묶음에 사용한다. 모든 제목·문단을 카드로 감싸지 않는다.

## 화면 검수

1. 처음 보는 사람이 화면의 목적과 주요 행동을 바로 찾을 수 있는가?
2. 라벨·placeholder·도움말·버튼이 같은 내용을 반복하지 않는가?
3. 목록에서 항목을 고르기 전에 불필요한 메타정보를 너무 많이 읽어야 하지는 않는가?
4. 내용이 짧거나 길어져도 묶음과 간격이 유지되는가? 320px·390px·PC와 부모 폭 240·320·510·800px의 Grid/Flex에서 확인했는가?
5. 검색 결과 없음, 오류, 대기, 선택 후와 키보드 이동이 자연스러운가?
6. 모달의 전체 폭 필드·2열 필드·실제 미디어가 부모 영역을 쓰는가? 견본 프레임이나 고정 폭이 남지 않았는가?
7. 내부 규격은 공식 크기·변형을 유지하고, 외부 배치는 서비스에서 정했는가?

기존 서비스 리디자인에서는 새로 구성한 화면과 원래 서비스의 필드·이벤트·권한·제출값도 함께 대조한다.
